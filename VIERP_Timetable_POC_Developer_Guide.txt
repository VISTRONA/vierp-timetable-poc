VIERP TIMETABLE POC
Complete Setup & Developer Guide
================================

PURPOSE
-------
This project automates timetable data entry into the VIERP system.

Instead of manually entering every timetable entry through dropdowns,
the user uploads a timetable Excel file. The system validates it,
converts it into structured records, stores the records in MySQL,
generates JSON files for each division, and exposes APIs consumed by
the Vue frontend.

ARCHITECTURE
------------
Excel
  -> Vue Frontend
  -> Grails Backend
  -> storage/uploads/
  -> Python DBMS Pipeline
  -> MySQL
  -> storage/timetable-json/
  -> Grails API
  -> Vue Frontend

TECH STACK
----------
Frontend : Vue.js + Vite
Backend  : Apache Grails 7.1.5
Java     : 17
Database : MySQL
Pipeline : Python 3
Excel    : openpyxl
API      : REST/JSON
Build    : Gradle
Version  : Git

5. DATABASE SCHEMA
------------------

The current database contains:

    CREATE DATABASE IF NOT EXISTS vierp_timetable_poc;

    USE vierp_timetable_poc;

    CREATE TABLE IF NOT EXISTS divisions (
        id INT AUTO_INCREMENT PRIMARY KEY,
        division_name VARCHAR(100) NOT NULL UNIQUE
    );

    CREATE TABLE IF NOT EXISTS timetable_entries (
        id INT AUTO_INCREMENT PRIMARY KEY,
        division_id INT NOT NULL,
        subject VARCHAR(100) NOT NULL,
        student_group VARCHAR(100) NOT NULL,
        teacher VARCHAR(255) NOT NULL,
        room VARCHAR(100) NOT NULL,
        day VARCHAR(20) NOT NULL,
        start_time TIME NOT NULL,
        end_time TIME NOT NULL,
        periods INT NOT NULL,
        type VARCHAR(20) NOT NULL,
        CONSTRAINT fk_timetable_division
            FOREIGN KEY (division_id)
            REFERENCES divisions(id)
            ON DELETE CASCADE
    );

Do not change the schema casually. If the schema changes, also update
database/schema.sql and the database documentation.

8. PYTHON PIPELINE
------------------

The main pipeline is:

    database/pipeline/run_pipeline.py

It performs:

    1. Read Excel
    2. Validate Excel
    3. Transform records
    4. Import into MySQL
    5. Generate JSON files

Pipeline modules:

    excel_reader.py
        Reads timetable Excel data.

    validator.py
        Validates columns, records and schedule.

    transformer.py
        Converts records into database format.

    mysql_loader.py
        Imports data into MySQL.

    timetable_repository.py
        Reads divisions and timetable records from MySQL.

    json_generator.py
        Generates division JSON files.

    run_pipeline.py
        Controls the complete process.


9. RUN PIPELINE MANUALLY
------------------------

From database/pipeline:

    python3 run_pipeline.py <path-to-excel-file>

Example:

    python3 run_pipeline.py ../../storage/uploads/timetable_list.xlsx

If no file is supplied:

    python3 run_pipeline.py

the pipeline searches storage/uploads/ for an .xlsx file.


10. IMPORTANT: UPLOAD REPLACES OLD DATA
---------------------------------------

The current POC treats each successful timetable upload as a complete
replacement of the previous timetable.

The database loader removes existing:

    timetable_entries
    divisions

and then imports the new timetable.

Therefore:

    Old timetable + New upload = New timetable

The system does NOT append timetable records.

After successful database import, old JSON files are removed before
fresh division JSON files are generated.

This prevents stale divisions from appearing in the API.

Example:

Previous upload:
    CIVIL
    ETC A
    CSE A

New upload:
    CIVIL

Expected JSON output:
    CIVIL.json

Only the new timetable dataset should remain.

14. UPLOAD API
--------------

Endpoint:

    POST /api/timetable/upload

Request type:

    multipart/form-data

File field:

    file

Example:

    curl -i -X POST       -F "file=@timetable_list.xlsx"       http://localhost:8080/api/timetable/upload

The backend:

    1. checks that a file was supplied
    2. checks that it is not empty
    3. checks maximum size
    4. checks .xlsx extension
    5. saves the file
    6. starts the Python pipeline
    7. validates the Excel
    8. imports the data into MySQL
    9. generates fresh JSON files
    10. returns the result

Current maximum upload size:

    10 MB

20. USING THE APPLICATION
-------------------------

1. Start MySQL.
2. Start Grails.
3. Start Vue.
4. Open the Vue URL.
5. Select a division/class.
6. The frontend requests its timetable.
7. The timetable is displayed.

To upload:

1. Click "Upload Timetable".
2. Select the .xlsx file.
3. Upload it.
4. Backend validates the file.
5. Python pipeline processes it.
6. MySQL is replaced with the new dataset.
7. Fresh JSON files are generated.
8. Frontend refreshes available divisions.
9. Select a division to view its timetable.


21. VIERP-STYLE FRONTEND
------------------------

The frontend is intentionally designed to resemble the existing VIERP
timetable page.

It contains:

    - VIT/institution header
    - user/profile area
    - breadcrumb
    - academic year
    - semester
    - division selection
    - timetable information
    - weekly timetable grid
    - timetable cards
    - upload action

The main improvement is that timetable data comes from the automated
Excel upload pipeline instead of manual dropdown entry.

26. COMMON PROBLEMS
-------------------

Java/Grails error involving unsupported class version:
    Check java -version and use Java 17.

Python cannot connect to MySQL:
    Check MySQL is running.
    Check database exists.
    Check database/pipeline/.env.
    Check MySQL username/password.

Missing Python module:
    cd database/pipeline
    source .venv/bin/activate
    pip install -r requirements.txt

Upload pipeline failure:
    Check the Grails terminal.
    Run the Python pipeline manually to see the detailed error.

Frontend cannot load timetable:
    Check Grails is running on port 8080.
    Check Vue is running on port 5173.
    Check vite.config.js proxy.
    Test /api/timetable/classes directly.

Old divisions appearing:
    Check storage/timetable-json/.
    Run the pipeline again.
    Confirm the database import completed successfully.

29. CURRENT POC LIMITATIONS
---------------------------

This is a proof of concept.

Before production, the following should be considered:

    - authentication
    - authorization / roles
    - stronger file/content validation
    - upload history
    - audit logs
    - better error reporting
    - asynchronous processing for large files
    - production file storage
    - upload filename collision handling
    - path safety
    - timetable conflict detection
    - database indexing
    - API security
    - better multi-period timetable rendering
    - deployment configuration
    - direct integration with actual VIERP/Eduplus backend

Do not introduce production architecture changes without agreement
from the project team.
